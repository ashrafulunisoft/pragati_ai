# 🧠 MCP কখন `SAFE` / `SUSPICIOUS` / `MALICIOUS` response দেয়?

> **⚠️ এই doc টা actual code-এর সাথে 100% align করা** — source:
> - `app/Services/McpSecurityService.php`
> - `app/Http/Middleware/McpMaliciousLoginMiddleware.php`

**সবচেয়ে গুরুত্বপূর্ণ কথা:** সিস্টেমে decision **binary (SAFE/MALICIOUS) না** — **৩টা tier** আছে:

| Decision | Risk Score | Action |
|---|---|---|
| `SAFE` | 0 – 49 | monitor / captcha |
| `SUSPICIOUS` | 50 – 79 | otp |
| `MALICIOUS` | 80 – 100 | block_ip |

# 🔌 পুরো Flow (actual implementation)

## Layer 1 — Rule Engine (Middleware)

`McpMaliciousLoginMiddleware` প্রতিটা login POST-এ চলে। প্রথমে Redis থেকে attempt count পড়ে:

```php
$ipKey    = "attack:login:ip:$ip";
$emailKey = "attack:login:email:$email";

$ipAttempts    = Redis::get($ipKey) ?? 0;
$emailAttempts = Redis::get($emailKey) ?? 0;
```

MCP (AI) তখনই call হয় **যখন threshold cross হয়**:

```php
if ($ipAttempts >= 5 || $emailAttempts >= 3) {
    $mcp = McpSecurityService::analyzeLogin([...]);
}
```

👉 অর্থাৎ attempt কম থাকলে AI call-ই হয় না (API খরচ বাঁচে)। Trigger point শুধু — **decision এখানেও হয় না।**

## Layer 2 — AI / Rule Hybrid (Service)

`analyzeLogin()` এ:
1. আগে **deterministic risk score** বের হয় (`getRiskScore`)
2. সেই score-এর উপর ভিত্তি করে **default** decision/action বানানো হয়
3. তারপর MiniMax AI-কে prompt পাঠানো হয়
4. AI-এর response **merge** হয় default-এর সাথে

### ⚠️ Critical: AI-এর নিজের decision override হয়

AI যা-ই বলুক, **final `decision` আর `recommended_action` risk_score থেকে deterministic threshold দিয়ে আবার set হয়:**

```php
// Override decision and recommended_action based on risk_score
$mcp['recommended_action'] = self::getRecommendedAction($mcp['risk_score']);

if ($mcp['risk_score'] >= 80) {
    $mcp['decision']    = 'MALICIOUS';
    $mcp['attack_type'] = 'brute_force';
} elseif ($mcp['risk_score'] >= 50) {
    $mcp['decision']    = 'SUSPICIOUS';
    $mcp['attack_type'] = 'credential_stuffing';
}
```

👉 মানে AI শুধু `risk_score` / `attack_type` / `confidence` দেয়, কিন্তু **final decision আর action rule-ই ঠিক করে।**

# ⏱️ MCP Response Time (latency)

`analyzeLogin()`-এ এখন response time measure হয় (code-তে যোগ করা হয়েছে):

```php
$startTime = microtime(true);            // AI call-এর আগে
// ... HTTP POST ...
$responseTimeMs = round((microtime(true) - $startTime) * 1000, 2);
```

- **কী measure হয়:** MiniMax AI HTTP call-এর full round-trip সময় (milliseconds)
- **কোথায় log হয়:** `response_time_ms` field → `MCP_DECISION` entry (`mcp_security.log`) + `[MCP Security] Analysis result` (`laravel.log`)

### Real measured value (live test)

| Test | Response time |
|---|---|
| Real MiniMax-M2.1 call (IP 8, Email 4) | **~5081 ms (~5.1 s)** |

> **দৃষ্টান্ত:** MiniMax-M2.1 model response-এর আগে `<think>…</think>` reasoning block দেয়, তাই round-trip **~5 সেকেন্ড** লাগে। AI response invalid JSON হলে system **fallback** (rule-based default) ব্যবহার করে — তাই block decision AI-র wait-এর উপর ঝুলে থাকে না (fail-open)। Fallback path-এও `response_time_ms` log হয়।

# 🧮 Risk Score Formula (getRiskScore)

```php
$baseScore = 0;

// IP attempts
if ($ipAttempts >= 10)      $baseScore += 50;
elseif ($ipAttempts >= 5)   $baseScore += 30;
elseif ($ipAttempts >= 3)   $baseScore += 15;

// Email attempts
if ($emailAttempts >= 5)    $baseScore += 40;
elseif ($emailAttempts >= 3) $baseScore += 25;

return min(100, $baseScore);   // cap 100
```

### স্কোর টেবিল:

| IP attempts | Email attempts | Score |
|---|---|---|
| 0–2 | 0–2 | 0 |
| 3–4 | 0–2 | 15 |
| 5–9 | 0–2 | 30 |
| 10+ | 0–2 | 50 |
| 3–4 | 3–4 | 40 |
| 5–9 | 3–4 | 55 |
| 10+ | 3–4 | 75 |
| 10+ | 5+ | 90 |

# 🎯 Decision + Action (getRecommendedAction)

```php
public static function getRecommendedAction(int $riskScore): string
{
    if ($riskScore >= 80)      return 'block_ip';
    elseif ($riskScore >= 50)  return 'otp';
    elseif ($riskScore >= 30)  return 'captcha';
    else                       return 'monitor';
}
```

### Complete mapping:

| Risk Score | Decision | attack_type | Action |
|---|---|---|---|
| 0 – 29 | `SAFE` | normal_user | `monitor` |
| 30 – 49 | `SAFE` | normal_user | `captcha` |
| 50 – 79 | `SUSPICIOUS` | credential_stuffing | `otp` |
| 80 – 100 | `MALICIOUS` | brute_force | `block_ip` |

# 🚫 Blocking Logic (Middleware)

Block হয় **দুটো condition-এর যেকোনো একটায়**:

```php
if ($mcp['decision'] === 'MALICIOUS') {
    $shouldBlock = true;
} elseif ($mcp['risk_score'] >= 80) {
    $shouldBlock = true;
}

if ($shouldBlock) {
    Redis::setex("blocked:ip:$ip", 3600, 1);   // 1 hour block
    event(new McpAttackDetected([...], $mcp)); // email alert
    return response()->json(['error' => '... Access blocked for 1 hour.'], 403);
}
```

👉 Block করলে IP **১ ঘণ্টার** জন্য Redis-এ store হয় + admin-কে email alert যায়।

# 🤖 Prompt-এ AI-কে যা বলা হয়

```json
{
  "decision": "SAFE or MALICIOUS",
  "attack_type": "brute_force | credential_stuffing | bot_attack | dos | normal_user",
  "risk_score": 0-100,
  "confidence": 0-1,
  "recommended_action": "block_ip | captcha | otp | monitor"
}
```

> **Note:** prompt-এ decision binary (`SAFE or MALICIOUS`) চাওয়া হয়, কিন্তু system নিজে `SUSPICIOUS` tier add করে risk_score override-এর মাধ্যমে। AI fail করলে **rule-based default** ব্যবহার হয় (**fail-open** — legit user block হয় না)।

# 🔐 Why hybrid (Rule + AI) is better than pure rule?

### ❌ Normal rule-based:

```txt
attempts > 5 = block
```

Problem: legit user block হয়, false positive, bad UX।

### ✅ এই system:

```txt
attempts > 5 → AI analyze → risk_score → tiered action
```

Benefits:

- **Tiered response** (monitor → captcha → otp → block_ip) — সবাইকে সরাসরি block করা হয় না
- AI fail করলেও **rule-based fallback** (fail-open)
- কম attempt-এ AI call হয় না → API cost কম
- Research-grade adaptive security
