## ১.১ কমেন্টের মর্মার্থ (বাংলায়)

> রুল-অনলি 21.2% থেকে রুল+AI 83.9% recall — এই লাফ **seed করা এক্সপেরিমেন্টের** "honest" AI মোড থেকে এসেছে, যেটা একটা *"competent simulated AI"* (নকল/সিমুলেটেড বিশ্লেষক)। অর্থাৎ এই লাফ **ডিপ্লয় করা MiniMax-M2.1 ইন্টিগ্রেশনের কার্যকারিতা প্রমাণ করে না**।
>
> **যা চেয়েছে:**
> 1. লাইভ মডেল রেসপন্স দিয়ে মূল্যায়ন আবার করুন
> 2. Prompt এবং response schema প্রকাশ করুন
> 3. বারবার রান করে variation (হার-কমা) রিপোর্ট করুন
> 4. প্রতিনিধিত্বমূলক attack distribution দিন
> 5. লাইভ-মডেলের confusion matrix সিমুলেশনের থেকে **আলাদা করে** দেখান

## ১.২ প্রজেক্টের এখনকার অবস্থা

| বিষয় | স্ট্যাটাস |
|---|---|
| লাইভ-মোড সাপোর্ট | ✅ আছে — `php artisan security:evaluate --ai=live` রিয়েল MiniMax API কল করে (একই production pipeline দিয়ে) |
| Prompt প্রকাশের উপাদান | ✅ কোডে আছে — `app/Mcp/SecurityPrompt.php` (fenced, pseudonymized); পেপারে Appendix-এ পুরোটা বসাতে হবে |
| Response schema | ✅ কোডে আছে — `{decision, attack_type, risk_score, confidence, recommended_action}`; Appendix-এ দিতে হবে |
| একাধিক seed-এ রান + mean±std | ❌ করা হয়নি — এখন পর্যন্ত শুধু seed 42, একবার |
| লাইভ বনাম সিমুলেশন আলাদা টেবিল | ❌ পেপারে নেই |

**গুরুত্বপূর্ণ বাস্তব তথ্য (লাইভ রানের আগে মাথায় রাখুন):**
- আগের একটি লাইভ মাপে MiniMax-M2.1 round-trip ছিল **~5.1 সেকেন্ড** (মডেল `<think>…</think>` ব্লক দেয়) — পেপারের টেবিলে 2.6–4.4s বলা আছে
- লাইভ মডেল মাঝে মাঝে invalid JSON দিতে পারে → `parseAiResponse()` null রিটার্ন করে → AI-unavailable হিসেবে গণ্য হয় — **এই হারটাও রিপোর্ট করতে হবে** (এটা সৎ রিপোর্টিংয়ের অংশ)
- খরচ: honest মোডে 186 event-এ ~40 AI কল; লাইভেও এরকম হবে → ৫টা seed = ~200 কল — কোটার হিসাব রাখুন

## ১.৩ কী কী করতে হবে

### কোড/হার্নেস পাশ (ছোট)
1. `SecurityEvaluateCommand.php`-এ **multi-seed সাপোর্ট** যোগ করুন: যেমন `--seeds=42,7,123,999,2026` — প্রতি seed-এ per-scenario confusion matrix জমা হবে, শেষে mean ± std রিপোর্ট
2. লাইভ রানের JSON আউটপুটে **AI parse-failure হার** (`ai_invalid_response` কাউন্টার) যোগ করুন
3. (ঐচ্ছিক) `--repeat=5` — একই seed-এ ৫ বার লাইভ রান করে run-to-run variance আলাদাভাবে দেখান

### এক্সপেরিমেন্ট
4. চালান:
   ```bash
   php artisan security:evaluate --ai=live --seed=42
   php artisan security:evaluate --ai=live --seed=7
   php artisan security:evaluate --ai=live --seed=123
   php artisan security:evaluate --ai=live --seed=999
   php artisan security:evaluate --ai=live --seed=2026
   ```
5. রিপোর্ট সংগ্রহ: `storage/app/security-evaluation/eval-live-*.md|json`

### ম্যানুস্ক্রিপ্ট
6. **নতুন টেবিল:** "Live-model results (5 runs, mean ± std)" — recall/accuracy/precision/F1/FPR, প্রতিটি attack class ধরে
7. **আলাদা লেবেল:** সিমুলেটেড (honest) ফলাফলের টেবিলের শিরোনামে "simulated analyst" স্পষ্ট লিখুন; লাইভ টেবিলে "live MiniMax-M2.1"
8. **Appendix A আপডেট:** পুরো prompt টেক্সট (pseudonymized ফিল্ডসহ), JSON response schema, `temperature=0`, `max_tokens`, timeout/retry সেটিং
9. Discussion-এ যোগ করুন: লাইভ মডেল সিমুলেশনের চেয়ে ভালো/খারাপ কেন — যেমন `<think>` ব্লক, JSON parse ফেল, latency

## ১.৬ ঝুঁকি ও ব্যাকআপ প্ল্যান

- **ঝুঁকি:** লাইভ মডেলের recall সিমুলেশনের চেয়ে কম হতে পারে (invalid JSON, বাস্তব মডেলের রায় ওঠানামা)
- **তবুও সৎ রিপোর্ট করুন** — রিভিউয়ার মিথ্যা উঁচু সংখ্যা চায় না, নির্ভরযোগ্য মাপ চায়। লাইভ ফলাফল যতই হোক, "measured, reproducible (seeded), fully disclosed" হলে কমেন্ট মিটবে
- যদি লাইভ ফল খারাপ আসে → prompt engineering (few-shot example যোগ, schema enforcement) করে আবার মাপুন — উন্নতির চিত্রটাও কাগজে দেখানো যায়
