## ৩.১ কমেন্টের মর্মার্থ (বাংলায়)

> Section 4.3 বলছে effective score হলো `S = max(S_rule, S_AI)` — কিন্তু **Algorithm 1-এ এই fused score কোথাও গণনা/ব্যবহার দেখানো নেই**। এছাড়া Algorithm 1 `token_428` কে SUSPICIOUS request-এ ধরে **অথচ শেষের non-MALICIOUS ব্রাঞ্চে `Allow` রিটার্ন করে** — অর্থাৎ ছদ্মকোড দাবি করা "enforced HTTP 428 step-up" মেকানিজমের সাথে মেলে না।
>
> **যা চেয়েছে:**
> 1. একটি **অদ্বিতীয়, executable decision sequence** (বা state-transition specification) দিন
> 2. `S_AI` কীভাবে পাওয়া হয় ও **কীভাবে bounded** — ব্যাখ্যা করুন
> 3. প্রতিটি SUSPICIOUS outcome সত্যিই পরিকল্পিত challenge ট্রিগার করে — **যাচাই করুন**

## ৩.২ প্রজেক্টের এখনকান অবস্থা (কোড = সত্যের উৎস)

**কোড ইতিমধ্যে সঠিক** — সমস্যা শুধু পেপারের pseudocode-এ। আসল middleware-এর সিদ্ধান্ত-ক্রম:

```
POST /login (email sanitized)
 │
 ① blocked early-exit: blocked:ip:{ip} বা blocked:email:{email} থাকলে → 403 (AI কল নেই)
 │
 ② Redis কাউন্টার পড়া: ipAttempts, emailAttempts
 │
 ③ Threshold gate: ipAttempts ≥ 5 OR emailAttempts ≥ 3 ? না হলে → next() (login চলতে থাকে)
 │
 ④ analyzeLogin():
 │     S_rule = getRiskScore()                    // deterministic rule score
 │     S_AI   = AI থেকে parsed risk_score (0–100 clamp; invalid → AI-unavailable)
 │     S      = max(S_rule, S_AI)                 // ← FUSION — Algorithm 1-এ এটা নেই!
 │     F1: S ≥ 80                        → MALICIOUS
 │     F2: AI=MALICIOUS ∧ S ≥ 50         → MALICIOUS
 │     F3: AI=SAFE(conf≥0.8) ∧ S 50–79   → SUSPICIOUS (bounded leniency)
 │     F4: S ≥ 50                        → SUSPICIOUS
 │     F5: else                          → SAFE
 │     + action = band(S): block_ip / otp / captcha / monitor
 │
 ⑤ MALICIOUS বা S ≥ 80 → blockIp() [NAT-aware scope] → 403 + alert event
 │
 ⑥ ai_available ∧ action ∈ {captcha, otp}:
 │     token ইতিমধ্যে solve করা? → verify() pass হলে next()
 │     না হলে → challenge issue → HTTP 428 ← এখানেই থামে (Allow নয়!)
 │
 ⑦ else (SAFE / ai নেই) → next()
 │
 ⑧ LoginController: Auth::attempt → fail হলে কাউন্টার increment; success হলে reset
```

**যাচাইযোগ্য প্রমাণ (টেস্ট):**
- `McpDecisionFusionTest` (৯টি) — `max()` floor, F2 escalation, F3 bounded leniency
- `McpChallengeEnforcementTest` (১০টি) — প্রতিটি SUSPICIOUS-band `otp/captcha` verdict-এ **428** ইস্যু হয়; MALICIOUS আগে 403 করে; degrade মোডে challenge নয়, N-strike
- Degraded (AI down) SUSPICIOUS → challenge নয়, N-strike throttle — এইটাও পেপারে বলা দরকার

## ৩.৩ কী কী করতে হবে (সবই ম্যানুস্ক্রিপ্টে)

1. **Algorithm 1 পুরো রিরাইট** — উপরের ①–⑦ ক্রমের মতো করে; বিশেষত:
   - ধাপ ④-এ **S-এর গণনা দেখান**: `S ← max(S_rule, S_AI)`
   - terminal non-MALICIOUS ব্রাঞ্চে `return Allow` **নয়** — `if action ∈ {captcha, otp} ∧ AI available: issue token; return 428` লিখুন
2. **`S_AI` এর বাউন্ডিং ব্যাখ্যা** (Section 4.3-এ বাক্য যোগ):
   - AI JSON থেকে parse হয়, `[0,100]`-এ clamp হয়
   - non-numeric/invalid → `ai_available = false` → rule-fallback
   - `S_AI < S_rule` হলে floor জেতে — AI স্কোর নামাতে পারে না
3. **Table 2 মিলিয়ে দিন** — ব্যান্ড → decision → enforced action (428 challenge / 403 block) কলাম যোগ করুন যাতে "SUSPICIOUS ⇒ otp ⇒ 428" চেইন দৃশ্যমান হয়
4. (ঐচ্ছিক শক্তিশালীকরণ) ছোট একটি **state-transition diagram** (state: NEW → ANALYZED → CHALLENGED(428) → VERIFIED/BLOCKED/ALLOWED) Figure হিসেবে দিন — রিভিউয়ার নিজেই এই বিকল্পের কথা বলেছে ("or equivalent state-transition specification")

## ৩.৫ রেসপন্স লেটারে যা লিখবেন (ইংরেজি ড্রাফট)

> **Comment 3:** Thank you — the published pseudocode was inconsistent with the implementation. Algorithm 1 has been rewritten as an unambiguous decision sequence: the fused score S = max(S_rule, S_AI) is now computed explicitly (line …); S_AI is parsed from the model's JSON response, clamped to [0,100], treated as unavailable when unparseable, and can never lower S below the deterministic rule score. The terminal non-malicious branch no longer returns Allow: when the recommended action is captcha/otp and the AI layer is available, the algorithm issues a single-use challenge token and returns HTTP 428; only SAFE outcomes (and solved challenges) proceed to the credential path. In degraded mode (AI unavailable) the 50–79 band is handled by the N-strike throttle instead of challenges, as now stated in Section 4.x. Table 2 includes the enforced action for every decision band. Unit tests McpDecisionFusionTest and McpChallengeEnforcementTest verify each branch.
